# Техническое задание: Telegram-бот для транскрибации аудио и видео

## Назначение

Telegram-бот для личного использования, который переводит аудио и видео в текст с максимальным качеством распознавания. Ключевая особенность — выбор между дословной расшифровкой (сохраняет слова-паразиты, паузы, запинки) и ИИ-конспектом (структурированное краткое содержание).

Версия 1 — под одного пользователя (владельца бота), без оплаты и лимитов. Код не усложнять под мультипользовательский режим заранее, но и не закладывать решений, которые сделают его невозможным в будущем.

## Пользовательский сценарий

1. Пользователь отправляет боту голосовое сообщение, аудио/видео файл или ссылку на YouTube
2. Бот сразу отвечает "Принял, обрабатываю…"
3. Бот скачивает (если это ссылка) и извлекает аудиодорожку из видео
4. Бот присылает дословный текст + кнопки «🤖 Сделать конспект» и, если источник был видео, «🎵 Прислать аудио отдельно»
5. При нажатии кнопки бот отдельным сообщением присылает нужный вариант — конспект или аудиофайл

## Функциональные требования

### 1. Приём контента
- Голосовые сообщения Telegram
- Аудиофайлы: mp3, wav, ogg, m4a, flac
- Видеофайлы, отправленные напрямую
- Пересланные голосовые/видеосообщения
- Текстовое сообщение со ссылкой на YouTube (в идеале — и на другие сайты, которые поддерживает yt-dlp)

### 2. Скачивание по ссылке
- Библиотека: **yt-dlp**
- Извлекать только аудиодорожку — экономит место и время обработки
- Авторизация — через куки, экспортированные из браузера (`--cookies-from-browser`)
- Скачанный файл удалять сразу после обработки, не хранить
- Если видео пришло файлом напрямую (не по ссылке) — извлекать аудиодорожку тем же способом, через ffmpeg

### 3. Распознавание речи
- Основная модель: **CrisperWhisper 2.0** (github.com/nyrahealth/CrisperWhisper)
  - Причина выбора: в отличие от обычного Whisper, модель различает на одном аудио два режима — verbatim (дословно, с запинками и словами-паразитами) и intended (причёсанный текст). Это напрямую закрывает требование к дословности
  - Работает на архитектуре faster-whisper, для комфортной скорости нужен GPU
- Fallback: если качество на русском при тестировании разочарует — переключиться на faster-whisper (large-v3)
- Язык распознаётся автоматически, приоритет — русский

### 4. Варианты вывода: дословно / конспект / аудио
Транскрибация выполняется один раз (это дорогая GPU-операция). Дальше — выбор представления:
- **Дословно** — сырой verbatim-вывод CrisperWhisper без изменений
- **Конспект (ИИ)** — тот же транскрипт уходит в LLM с промптом на структурированную выжимку
- **Аудио отдельно** — если источник был видео (файл или ссылка), бот может прислать саму извлечённую аудиодорожку файлом, без транскрибации — пригодится, когда текст не нужен, а нужно просто аудио

Конспект генерируется по запросу (по нажатию кнопки), а не автоматически всегда — это экономит вызовы LLM API. Извлечение аудио — лёгкая операция без GPU (ffmpeg), поэтому этот вариант можно отдавать быстро, не дожидаясь готовности текста.

### 5. ИИ для конспекта
- Провайдер: **Google Gemini API, бесплатный тариф** (модель Gemini 2.5 Flash через Google AI Studio)
- Промпт: убрать слова-паразиты и повторы, структурировать по смысловым пунктам, ничего не додумывать и не искажать факты и цифры

### 6. Большие и длинные файлы
- Стандартный Telegram Bot API: приём файлов до 20 МБ, отправка до 50 МБ
- Если этого не хватает на практике — поднять **Local Bot API Server** (снимает лимит примерно до 2 ГБ). Отдельный опциональный модуль, не обязателен для первой версии
- Обработка асинхронная: бот не блокируется на время ожидания, результат приходит отдельным сообщением, когда готов

### 7. Обработка ошибок
- Неподдерживаемый формат / битый файл — понятное сообщение пользователю, а не падение бота
- Ссылка не скачалась (сайт заблокировал/удалил видео) — сообщить об этом текстом
- GPU/API недоступны — одна повторная попытка, затем понятное сообщение об ошибке

## Технический стек

| Компонент | Выбор |
|---|---|
| Язык | Python 3.11+ |
| Telegram-фреймворк | aiogram (async) |
| Скачивание видео/аудио | yt-dlp |
| Транскрибация | crisperwhisper (пакет), запуск на GPU |
| ИИ-конспект | google-generativeai (Gemini API) |
| Большие файлы | telegram-bot-api (локальный сервер), опционально |
| Видео → аудио | ffmpeg (его же под капотом использует yt-dlp) |

## Структура проекта

```
bot/
├── main.py                   # точка входа, запуск бота
├── config.py                  # токены и ключи из переменных окружения
├── handlers/
│   ├── media.py                # приём голосовых/аудио/видео
│   ├── links.py                 # приём ссылок на YouTube
│   └── mode_toggle.py           # кнопка "Сделать конспект"
├── services/
│   ├── downloader.py             # обёртка над yt-dlp
│   ├── transcriber.py             # обёртка над CrisperWhisper
│   └── summarizer.py              # обёртка над Gemini API
├── requirements.txt
└── .env.example                 # шаблон переменных окружения
```

## Переменные окружения

```
TELEGRAM_BOT_TOKEN=
GEMINI_API_KEY=
```

## Инфраструктура

- GPU нужен только на время транскрибации — брать serverless-аренду (например RunPod), оплата по факту использования, без постоянного дорогого сервера
- Лёгкая логика самого бота (приём сообщений, роутинг) может работать отдельно на дешёвом always-on сервере

## Осознанно не входит в v1

- Оплата и подписки
- Лимиты на пользователя, мультитенантность
- Разделение по спикерам (диаризация)
- Публичный запуск / маркетинг

## Критерии готовности

- [ ] Голосовое сообщение → дословный текст
- [ ] Ссылка на YouTube → аудио → дословный текст
- [ ] Видео (файл или ссылка) → можно получить только аудиофайл, без транскрибации
- [ ] Кнопка «Сделать конспект» работает поверх готового транскрипта
- [ ] Файлы до 20 МБ обрабатываются без ошибок
- [ ] Бот не блокируется во время обработки (асинхронно)
- [ ] Понятные сообщения об ошибках при сбоях
